# 2B1Q (2 Bits to 1 Quaternary Symbol)

2B1Q is a **multilevel code** that represents 2 data bits as a single 4-level (quaternary) symbol. It's the foundation for understanding efficient multilevel encoding.

## Definition

**2B1Q encoding rule:**

Groups of 2 bits are mapped to one of four voltage levels:

| 2-Bit Pattern | Voltage Level | Mnemonic |
|---|---|---|
| 00 | -3V | Most negative |
| 01 | -V | Negative |
| 10 | +V | Positive |
| 11 | +3V | Most positive |

**Key insight:** 2 bits → 1 symbol means r = 2 (twice the efficiency of 1-bit-per-symbol codes).

## Example: Encoding the Bit Stream `11 10 00 01`

```
Group the bits:
(11) (10) (00) (01)

Apply the mapping:
11 → +3V
10 → +V
00 → -3V
01 → -V

Voltage waveform:
+3V |     ___
    |    /   \
 +V |   /     \___
    |  |           \
  0 |__|___________|____
    |               \
 -V |                \___
    |
-3V |

Time: T_s, 2T_s, 3T_s, 4T_s

where T_s = 2×T_b (symbol period is twice the bit period)
```

## Signal Properties

| Property | Value |
|----------|-------|
| **Voltage levels** | 4 (-3V, -V, +V, +3V) |
| **r factor** | 2 (2 data bits per symbol) |
| **Data bits per symbol** | 2 |
| **Signal rate** | = Bit rate / 2 |
| **Bandwidth** | ~= 0.5 × Bit rate |
| **Voltage separation** | 2V between consecutive levels |
| **DC component** | Depends on data |
| **Self-synchronization** | No (transitions depend on data) |
| **Practical use** | ISDN (older), DSL (older modems) |

## Efficiency Advantage: The Core Idea

```
Compare to Unipolar NRZ (1 bit per symbol):

Unipolar NRZ:
Bit rate: 8 kbps
Signal rate: 8 kbaud
Levels needed: 2 (0V, +V)
Bandwidth: ~8 kHz

2B1Q:
Bit rate: 8 kbps (same!)
Signal rate: 4 kbaud (half!)
Levels needed: 4 (-3V, -V, +V, +3V)
Bandwidth: ~4 kHz (half!)

Same data rate, half the bandwidth!
Trade-off: Distinguishing 4 levels is harder than 2 levels in noise.
```

## The Challenge: Detecting Multiple Levels

With only 2 levels (binary), the receiver decides: "Is the voltage closer to level 0 or level 1?"

With 4 levels (quaternary), the receiver must decide: "Which of 4 levels is closest to the received voltage?"

```
Binary (2 levels):        Quaternary (4 levels):
Decision threshold = 0V   Decision thresholds = -2V, 0V, +2V

Received:+0.3V            Received: -0.5V
Is it > 0V?               Which range?
Yes → Decode as 1         -2V < -0.5V < 0V → Decode as 01

Simpler!                  More complex!
                          
Noise immunity = Worse    Noise immunity = Much worse
(threshold margin = V/2)  (threshold margin = V/2)
```

### Example: How Noise Affects Detection

```
Transmitted: 4 symbols (11, 10, 00, 01)
Expected levels: +3V, +V, -3V, -V

Received with noise:
Received: +2.9V, +0.8V, -2.2V, -1.1V

Correct detection? Yes (all within ±V of expected)

What if noise is stronger?
Received: +1.5V, +1.8V, -0.5V, +0.3V
           (±V error on each)

Decision:
+1.5V is equally close to +V (+0.5V) and +3V (-1.5V) → ERROR
+1.8V is closer to +3V (-1.2V) than +V (+0.8V) → Maybe OK
-0.5V is closer to -V (+0.5V) than -3V (-2.5V) → OK
+0.3V is closer to +V (-0.7V) than -V (-1.3V)? → ERROR

2 out of 4 symbols decoded incorrectly!
BER increases significantly.
```

## Encoding Algorithm

```
Algorithm: 2B1Q_Encode(bitstream, voltage_level_V)
  
  // Build codeword mapping
  mapping = {
    "00": -3*V,
    "01": -V,
    "10": +V,
    "11": +3*V
  }
  
  // Process bits in groups of 2
  for i = 0 to length(bitstream) - 1, step 2:
    two_bits = bitstream[i:i+2]
    voltage_symbol = mapping[two_bits]
    
    output voltage_symbol
    hold for duration T_s = 2*T_b
```

## Decoding Algorithm

```
Algorithm: 2B1Q_Decode(received_signal, V)
  
  levels = [-3*V, -V, +V, +3*V]
  
  for each symbol period T_s:
    sample_voltage = signal at T_s/2 (mid-point of symbol)
    
    // Find closest level
    closest_level = levels[0]
    min_distance = |sample_voltage - closest_level|
    
    for each level in levels:
      distance = |sample_voltage - level|
      if distance < min_distance:
        min_distance = distance
        closest_level = level
    
    // Decode to bits based on closest level
    if closest_level == -3*V:
      output bits = "00"
    else if closest_level == -V:
      output bits = "01"
    else if closest_level == +V:
      output bits = "10"
    else if closest_level == +3*V:
      output bits = "11"
```

## Real-World Use: ISDN and DSL

### ISDN (Integrated Services Digital Network)

```
ISDN BRI (Basic Rate Interface):
Data rate: 144 kbps (64 + 64 + 16 kbps for bearer + signaling)
Channel: Twisted pair

Using 2B1Q:
f_b = 144 kbps
f_s = 144 / 2 = 72 kbaud
BW ≈ 72 kHz

Why 2B1Q?
- Twisted pair over distances up to 5-6 km
- Bandwidth limited to ~100 kHz
- 2B1Q fits easily (72 kHz << 100 kHz available)
- 4 levels manageable with good equalizers
- Used in millions of installations worldwide
```

### Early DSL (Digital Subscriber Line)

```
DSL modem specifications:
Download: 56 kbps (originally, T1 limit)
Channel: Voice-grade twisted pair (3.4 kHz nominal, ~1 MHz usable)

Using 2B1Q:
f_b = 56 kbps
f_s = 28 kbaud
BW ≈ 28 kHz

Why 2B1Q?
- Fits within the voice band without interference
- Simple modulation/demodulation
- Cost-effective for legacy systems
- Evolved into more complex schemes (2B1Q was just the start)
```

## Advantages

✓ **Bandwidth efficient** — 2× more efficient than binary codes (r = 2)  
✓ **Simple mapping** — Just 16 bits → 4 symbols (easy lookup table)  
✓ **Proven in practice** — Used in millions of ISDN modems  
✓ **Understandable** — Good teaching example of multilevel codes  

## Disadvantages

❌ **Noise sensitive** — 4 levels harder to distinguish than 2 levels  
❌ **No DC-free guarantee** — DC component depends on data  
❌ **No self-synchronization** — Transitions depend on data pattern  
❌ **Requires precise levels** — All 4 levels must be maintained precisely  

## The SNR Penalty

**Signal-to-Noise Ratio (SNR) trade-off:**

For the same noise level, using 4 levels instead of 2 costs about **6 dB in SNR**.

```
Mathematical proof:

For 2-level binary:
SNR_binary = (2V)^2 / (12 × σ_noise^2)

For 4-level quaternary:
SNR_quaternary = (2V)^2 / (12 × σ_noise^2)

Wait, they're the same! But...

The threshold margin changes:
- Binary: ±V from each decision threshold
- Quaternary: ±V/3 from each level

With same noise σ, the 4-level system has worse threshold margin.

Result: For same bit error rate, you need:
SNR_quaternary ≈ 10 × SNR_binary (approximately 10 dB higher)

Or: For same SNR, quaternary has ~10-100× higher BER.
```

## Bandwidth Calculation Example

**Problem:** A DSL system transmits 2 Mbps using 2B1Q over a twisted pair with maximum 500 kHz bandwidth. Is this feasible?

**Solution:**
```
f_b = 2 Mbps
r = 2
f_s = f_b / r = 2 Mbps / 2 = 1 Mbaud

BW needed ≈ f_s = 1 MHz

Available BW: 500 kHz

1 MHz > 500 kHz

NOT FEASIBLE. The system would need either:
1. Lower bit rate (e.g., 1 Mbps → 500 kHz needed)
2. Higher-order modulation (e.g., r = 3 or 4)
3. Better channel (wider bandwidth)
```

## Exam Questions Likely on 2B1Q

**Q1:** "Encode `10 01 11 00` in 2B1Q."  
**Answer:** Apply mapping: +V, -V, +3V, -3V

**Q2:** "A 2B1Q system has 4 signal levels spaced 2V apart. If the received signal has ±0.5V noise, what's the error probability?"  
**Answer:** Threshold margin = 1V. Noise magnitude ±0.5V means ~20% of symbol periods have errors. BER is significant.

**Q3:** "Why is 2B1Q more bandwidth-efficient than Manchester?"  
**Answer:** r = 2 means symbol rate is half, so BW ≈ 0.5× baseline. Manchester is r = 1, so BW ≈ 2× baseline.
