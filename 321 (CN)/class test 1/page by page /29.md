## 2. Deep Dive: Simple vs. Sophisticated Metrics


### DVR: Simple Metrics (Hop Count)

In basic DVR, every link has a cost of **1**. The algorithm only cares about the number of routers between the source and destination.

- **The Logic**: "The path with 2 hops is always better than the path with 5 hops."
    
- **The Flaw**: DVR might choose a 2-hop path over a 56kbps dial-up link instead of a 5-hop path over 10Gbps fiber. It is "bandwidth-blind."
    

### LSR/OSPF: Sophisticated Metrics

LSR allows for weighted costs based on the actual characteristics of the link.

- **Bandwidth (BW)**: OSPF often uses the formula $Cost = 10^8 / \text{bandwidth in bps}$. A 100Mbps link has a cost of 1, while a 10Mbps link has a cost of 10.
    
- **Delay**: As we discussed for Page 24, using ECHO packets to measure RTT.
    
- **Load/Queuing**: If a router's buffer is full, the link cost can temporarily increase to discourage more traffic from entering that "traffic jam."
    
- **Reliability**: If a link drops packets frequently, it can be assigned a higher cost.
    

**Example**: LSR would gladly take a 10-hop path if every hop is a high-speed fiber link, rather than a 1-hop path that is congested or slow.

## 3. OSPF (Open Shortest Path First)

OSPF is the most common implementation of Link State Routing. The "Open" just means it’s a public standard, not proprietary.

### LSA Flooding Logic

In OSPF, routers don't just send "packets"; they send **LSAs (Link State Advertisements)**. When a router receives an LSA with a specific sequence number ($Seq_{recv}$), it compares it to its stored sequence number ($Seq_{stored}$):

1. **If** $Seq_{recv} > Seq_{stored}$: This is fresh news. Update the local database and propagate/flood it to all other lines.
    
2. **If** $Seq_{recv} < Seq_{stored}$: This is old news. The sender is outdated! Send our stored info _back_ to them to bring them up to speed.
    
3. **If** $Seq_{recv} == Seq_{stored}$: Duplicate info. Ignore it (but acknowledge it so they stop sending).
    

## 4. The "Router Reset" Problem

What happens if a router crashes, loses its memory, and reboots with $Seq = 0$?

- **The Conflict**: Other routers in the network still remember the old, high sequence number (e.g., $Seq = 1000$).
    
- **The Fix**: When the rebooted router sends $Seq = 0$, the neighbors will notice it’s smaller than their stored value ($1000$). Following the logic above, they send the _correct_ current sequence info back to the rebooted router.
    
- **The Result**: The rebooted router realizes where it left off and sets its next sequence number to $1001$. This is a much more elegant solution than waiting for an "Age" timer to expire.
    

## 5. Hierarchy: Areas and Backbones

Your notes mention "Administrative control bodies." Large networks are organized into **Areas**:

- **Internal Routers**: Only know the topology of their own area.
    
- **Area Border Routers (ABR)**: Summarize routes from their area and talk to the **Backbone Area**.
    
- **Backbone (Area 0)**: The central hub that connects all other areas. This hierarchy keeps the Link State database from getting too massive for any single router to handle.
    

### Why does this matter for a BUET student?

In your labs, you'll likely configure OSPF. Understanding that $Seq_{recv} > Seq_{stored}$ logic is key to debugging why a router isn't picking up your config changes.
