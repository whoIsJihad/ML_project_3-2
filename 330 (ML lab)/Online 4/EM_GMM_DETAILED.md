## What is a Gaussian Mixture Model?

### The Core Idea

A **Gaussian Mixture Model** is a probabilistic model that says:

> "My data is a mixture of K Gaussian distributions. I don't know which sample came from which Gaussian, but I can learn them."

**Generative Model Perspective:**

To generate a new data point from a GMM:
1. Pick a cluster k from {1, 2, ..., K} with probability πₖ (the "mixing weight")
2. Sample a point from that cluster's Gaussian: x ~ N(μₖ, Σₖ)
3. Observe x

The hidden part: We see x, but not which cluster it came from.

### Parameters of a GMM

A GMM with K components has these parameters:

| Parameter | Symbol | Meaning | Shape |
|-----------|--------|---------|-------|
| Means | μ₁, μ₂, ..., μₖ | Center of each cluster | K × d |
| Covariances | Σ₁, Σ₂, ..., Σₖ | Spread of each cluster | K × d × d |
| Mixing weights | π₁, π₂, ..., πₖ | Probability of each cluster | K |

**Constraint:** π₁ + π₂ + ... + πₖ = 1 (mixing weights sum to 1)

---

## The Problem: Learning Hidden Cluster Assignments

### Why This is Hard

Imagine you have data X = {x₁, x₂, ..., xₙ} sampled from a GMM with K=3 clusters.

**What you observe:**  
A cloud of n points. That's it.

**What you don't know:**
- Which cluster each point came from (hidden assignment z)
- Where each cluster is centered (μₖ)
- How spread out each cluster is (Σₖ)
- What's the probability of each cluster (πₖ)

### The Chicken-and-Egg Problem

```
To learn the parameters (μ, Σ, π), I need to know which cluster each point belongs to.
        ↓
To know which cluster a point belongs to, I need to know the parameters (μ, Σ, π).
        ↓
Infinite loop! 🔄
```

### Maximum Likelihood Estimation (MLE)

We want to find parameters θ = {μ, Σ, π} that maximize the likelihood:

$$P(X|\theta) = \prod_{i=1}^{n} P(x_i|\theta)$$

For each sample, we marginalize over hidden clusters:
$$P(x_i|\theta) = \sum_{k=1}^{K} \pi_k \cdot N(x_i | \mu_k, \Sigma_k)$$

**Problem:** This likelihood is non-convex and hard to optimize directly.

---

## The Solution: Expectation-Maximization

### The Big Idea

EM is an iterative algorithm that **solves the chicken-and-egg problem** by alternating:

1. **E-Step (Expectation):** "Given current parameters, what's the probability each sample belongs to each cluster?"
2. **M-Step (Maximization):** "Given these soft assignments, what parameters best explain the data?"
3. **Repeat** until the likelihood stops improving (convergence)

### Why It Works

The key insight: **Soft assignments instead of hard assignments**

Instead of forcing each point into ONE cluster (hard): "This point is definitely cluster 1"

EM uses SOFT assignments (probabilities): "This point is 70% cluster 1, 20% cluster 2, 10% cluster 3"

This allows points near cluster boundaries to contribute to BOTH clusters, which is more realistic.

---

## E-Step: Computing Responsibilities

### What Are Responsibilities?

**Responsibility** $r_{ik}$ = The probability that sample $x_i$ was generated by cluster $k$.

It answers the question: *"What's the chance this point came from cluster k?"*

### The Formula

$$r_{ik} = \frac{\pi_k \cdot N(x_i | \mu_k, \Sigma_k)}{\sum_{j=1}^{K} \pi_j \cdot N(x_i | \mu_j, \Sigma_j)}$$

### Breaking It Down

**Numerator:** $\pi_k \cdot N(x_i | \mu_k, \Sigma_k)$
- $\pi_k$: Prior probability of cluster k (mixing weight)
- $N(x_i | \mu_k, \Sigma_k)$: "How likely is $x_i$ under cluster k's Gaussian?"
- Product: "How likely is $x_i$ overall from cluster k?"

**Denominator:** $\sum_{j=1}^{K} \pi_j \cdot N(x_i | \mu_j, \Sigma_j)$
- Normalize: Consider ALL clusters
- Ensure probabilities sum to 1

### Example Calculation

Say we have 2 clusters and one sample point:
- Cluster 1: μ₁ = [0, 0], Σ₁ = I, π₁ = 0.6
- Cluster 2: μ₂ = [5, 5], Σ₂ = I, π₂ = 0.4
- Sample: x = [1, 1]

**Step 1:** Compute Gaussian likelihoods
- $N(x | \mu_1, \Sigma_1) = 0.05$ (fairly likely from cluster 1)
- $N(x | \mu_2, \Sigma_2) = 0.0001$ (very unlikely from cluster 2)

**Step 2:** Weight by mixing
- $\pi_1 \cdot N(x | \mu_1, \Sigma_1) = 0.6 \times 0.05 = 0.03$
- $\pi_2 \cdot N(x | \mu_2, \Sigma_2) = 0.4 \times 0.0001 = 0.00004$

**Step 3:** Normalize
- Denominator = 0.03 + 0.00004 ≈ 0.03004
- $r_{1} = 0.03 / 0.03004 ≈ 0.998$ (99.8% cluster 1)
- $r_{2} = 0.00004 / 0.03004 ≈ 0.002$ (0.2% cluster 2)

**Interpretation:** The point is very close to cluster 1's center, so it's almost certainly from cluster 1.

### Properties of Responsibilities

1. **Probabilities:** $0 \leq r_{ik} \leq 1$ (between 0 and 1)
2. **Normalized:** For each sample i: $\sum_{k=1}^{K} r_{ik} = 1$ (probabilities sum to 1)
3. **Interpretation:** 
   - $r_{ik} \approx 1$: Sample definitely from cluster k
   - $r_{ik} \approx 0.5$: Sample equally likely from two clusters (boundary point)
   - $r_{ik} \approx 0$: Sample definitely not from cluster k

## M-Step: Updating Parameters

### Overview

Given responsibilities $r_{ik}$ (how much each sample "belongs" to each cluster), update:
- Means: μₖ
- Covariances: Σₖ  
- Mixing weights: πₖ

The key idea: **Weighted estimation**

Each sample contributes to a cluster's parameters proportionally to its responsibility for that cluster.

### Step 1: Compute Effective Count

$$N_k = \sum_{i=1}^{n} r_{ik}$$

This is the **soft count** of points assigned to cluster k.

**Interpretation:**
- If all points have high responsibility for cluster k: $N_k \approx n$
- If points are spread among clusters: $N_k < n$
- This is NOT an integer (it's a sum of fractional assignments)

**Intuition:** It's like asking "How many points, on weighted average, belong to cluster k?"

### Step 2: Update Mean

$$\mu_k^{\text{new}} = \frac{1}{N_k} \sum_{i=1}^{n} r_{ik} \cdot x_i$$

This is a **weighted average** of all samples, weighted by their responsibility for cluster k.

**Why this makes sense:**
- Samples with high $r_{ik}$ pull the mean toward them
- Samples with low $r_{ik}$ barely influence the mean
- It's the centroid of the weighted point cloud

**Example:**
```
Cluster k responsibilities: r_1k = 0.9, r_2k = 0.1, r_3k = 0.05
Points:                      x_1 = [1,1], x_2 = [2,2], x_3 = [100,100]

μ_k = (0.9*[1,1] + 0.1*[2,2] + 0.05*[100,100]) / (0.9 + 0.1 + 0.05)
    = ([0.9 + 0.2 + 5, 0.9 + 0.2 + 5]) / 1.05
    = [6, 6] / 1.05
    ≈ [5.7, 5.7]
```

The mean is pulled toward x₁ (strong responsibility) and slightly toward x₃ (weak responsibility).

### Step 3: Update Covariance

$$\Sigma_k^{\text{new}} = \frac{1}{N_k} \sum_{i=1}^{n} r_{ik} \cdot (x_i - \mu_k)(x_i - \mu_k)^T$$

This is a **weighted covariance matrix**.

**Breakdown:**
- $(x_i - \mu_k)$: Deviation from cluster mean
- $(x_i - \mu_k)(x_i - \mu_k)^T$: Outer product (gives d × d matrix)
- $r_{ik}$ weights: Points with high responsibility contribute more
- Divide by $N_k$: Normalize

**Why this makes sense:**
- Points far from μₖ with high responsibility → large Σₖ
- Points close to μₖ → small Σₖ
- It's the spread of the weighted point cloud

### Step 4: Update Mixing Weight

$$\pi_k^{\text{new}} = \frac{N_k}{n}$$

This is the **fraction of data softly assigned to cluster k**.

**Interpretation:**
- If $N_k$ is large (many points assigned to k) → πₖ close to 1
- If $N_k$ is small (few points assigned to k) → πₖ close to 0
- Automatically balances the clusters

**Example with 3 clusters, n=100:**
- N₁ = 50, N₂ = 40, N₃ = 10
- π₁ = 50/100 = 0.5
- π₂ = 40/100 = 0.4
- π₃ = 10/100 = 0.1

## The Full Algorithm Loop

### Pseudocode

```
Initialize: μ₁, μ₂, ..., μₖ (random or k-means++)
           Σ₁, Σ₂, ..., Σₖ (identity matrix)
           π₁, π₂, ..., πₖ (uniform: 1/K each)

ll_old = -∞

for iteration in 1 to max_iter:
    # E-STEP: Compute responsibilities
    for each sample i:
        for each cluster k:
            r_ik = (π_k * N(x_i | μ_k, Σ_k)) / Σ_j(π_j * N(x_i | μ_j, Σ_j))
    
    # M-STEP: Update parameters
    for each cluster k:
        N_k = Σ_i r_ik
        
        μ_k = (1/N_k) * Σ_i (r_ik * x_i)
        
        Σ_k = (1/N_k) * Σ_i (r_ik * (x_i - μ_k)(x_i - μ_k)^T)
        
        π_k = N_k / n
    
    # CHECK CONVERGENCE
    ll_new = Σ_i log(Σ_k π_k * N(x_i | μ_k, Σ_k))
    
    if |ll_new - ll_old| < tolerance:
        break
    
    ll_old = ll_new

return μ, Σ, π
```

### Computational Complexity

For each iteration:
- **E-step:** O(n × K × d) — compute all responsibilities
- **M-step:** O(n × K × d²) — update covariances
- **Overall:** O(n × K × (d + d²)) per iteration

Typical: 10-100 iterations until convergence.

## Convergence and Stopping

### Log-Likelihood as Progress Meter

We monitor the **log-likelihood** to check if EM is improving:

$$LL = \sum_{i=1}^{n} \log\left(\sum_{k=1}^{K} \pi_k \cdot N(x_i | \mu_k, \Sigma_k)\right)$$

This is $\log P(X|\theta)$ — the log probability of observing all data given parameters.

### Properties of Log-Likelihood

1. **Monotonically non-decreasing:** EM always increases (or maintains) the LL
2. **Bounded above:** Cannot increase infinitely
3. **Convergence:** Eventually stabilizes (approaches local maximum)

### Stopping Criteria

**Method 1: Fixed iterations**
```python
for i in range(max_iter):  # e.g., 100 iterations
    e_step()
    m_step()
```

**Method 2: Monitor LL change**
```python
for iteration in range(max_iter):
    e_step()
    m_step()
    
    ll_new = compute_log_likelihood()
    if abs(ll_new - ll_old) < tolerance:  # e.g., 1e-4
        break
    ll_old = ll_new
```

**Method 3: Monitor parameter change**
```python
for iteration in range(max_iter):
    mu_old = mu.copy()
    e_step()
    m_step()
    
    if np.max(np.abs(mu - mu_old)) < tolerance:
        break
```

### Typical Behavior

```
Iteration 1:  LL = -1000.0
Iteration 2:  LL = -500.0    (huge jump)
Iteration 3:  LL = -450.0    (good improvement)
Iteration 4:  LL = -440.0    (smaller improvement)
Iteration 5:  LL = -439.0    (tiny improvement)
Iteration 6:  LL = -438.9    (almost converged)
...
Iteration 50: LL = -438.50   (plateaued, stop)
```

---

## Why EM Works: Monotonic Improvement

### The Mathematical Guarantee

**Theorem:** Each iteration of EM increases (or maintains) the log-likelihood.

$$LL(\theta^{(t+1)}) \geq LL(\theta^{(t)})$$

### Intuitive Explanation

Think of likelihood as a landscape (hills and valleys).

**E-step:** "Assume current parameters are correct. Estimate where the data came from."

**M-step:** "Adjust parameters uphill based on estimated data sources."

This greedy uphill movement guarantees we never go downhill.

### Why Not Global Optimum?

EM finds a **local maximum**, not the global maximum.

- **Good news:** Guaranteed to improve at each step
- **Bad news:** Might get stuck in a local optimum

**Solution:** Try multiple random initializations, keep the one with highest LL.

## Comparison with K-Means

### Side-by-Side

| Aspect | K-Means | EM/GMM |
|--------|---------|--------|
| **Assignment** | Hard (each point to exactly 1 cluster) | Soft (probability for each cluster) |
| **Cluster representation** | Center μₖ only | Full distribution: μₖ, Σₖ, πₖ |
| **E-Step** | Assign to closest center | Compute responsibilities |
| **M-Step** | Update center as mean | Update mean, covariance, weight |
| **Output** | Cluster labels | Cluster labels + probabilities |
| **Speed** | Faster | Slower (covariance updates) |
| **Interpretability** | Simple, clear clusters | Probabilistic interpretation |
| **Convergence guarantee** | Local convergence | Guaranteed LL improvement |

### Example: Boundary Point

Consider a point exactly ON the boundary between clusters 1 and 2.

**K-Means:**
```
Point assigned to cluster 1 (arbitrary, based on distance)
- Cluster 1 mean: includes this point
- Cluster 2 mean: does not include this point
```

**EM/GMM:**
```
Point has responsibility 0.5 for cluster 1 and 0.5 for cluster 2
- Cluster 1 mean: influenced by 0.5 × point
- Cluster 2 mean: influenced by 0.5 × point
- More realistic!
```

## Common Issues and Fixes

### Issue 1: Singular Covariance Matrix

**Problem:** A cluster's covariance becomes non-invertible (determinant = 0).

**Cause:**
- All points assigned to one cluster → Σ collapses to a line or point
- Numerical precision issues

**Fix:**
```python
# Add regularization
Sigma_k = Sigma_k + lambda_reg * np.eye(d)

# Or use tied covariances
Sigma_shared = (1/K) * np.sum([Sigma_k for k in range(K)])

# Or constrain diagonal to minimum value
np.fill_diagonal(Sigma_k, np.maximum(np.diag(Sigma_k), min_variance))
```

### Issue 2: Empty Clusters

**Problem:** A cluster gets no responsibility (all $r_{ik} \approx 0$ for some k).

**Cause:**
- Poor initialization
- K too large for the data
- Local minimum

**Symptoms:**
- πₖ → 0
- μₖ and Σₖ become degenerate
- Log-likelihood plateaus

**Fix:**
```python
# Merge empty clusters
if N_k < n_threshold:
    # Reassign cluster k to a random point
    mu_k = X[np.random.randint(n)]
    
# Or re-initialize from scratch with different seeds

# Or reduce K
```

### Issue 3: Slow Convergence

**Problem:** EM takes too many iterations.

**Cause:**
- Poor initialization (start far from optima)
- Overlapping clusters (hard to separate)
- Too strict tolerance

**Fix:**
```python
# Use k-means++ initialization instead of random
from sklearn.cluster import kmeans_plusplus
mu = kmeans_plusplus(X, n_clusters=K)[0]

# Loosen tolerance
tolerance = 1e-3  # instead of 1e-6

# Set max_iter limit
max_iter = 100
```

### Issue 4: Local Optima

**Problem:** EM converges to a suboptimal solution.

**Cause:** Random initialization led to a local maximum.

**Fix:**
```python
best_ll = -np.inf
best_theta = None

for trial in range(10):  # Try 10 random starts
    mu, Sigma, pi = em_gmm(X, K, random_state=trial)
    ll = compute_log_likelihood(X, mu, Sigma, pi)
    
    if ll > best_ll:
        best_ll = ll
        best_theta = (mu, Sigma, pi)

return best_theta
```

### Issue 5: Overfitting (Too Many Components)

**Problem:** Model fits noise, not true structure.

**Symptoms:**
- Very high LL for training data
- Poor LL on test data
- Tiny clusters with huge specific covariances

**Fix: Use information criteria**

**AIC (Akaike Information Criterion):**
$$AIC = -2 \cdot LL + 2 \cdot p$$

**BIC (Bayesian Information Criterion):**
$$BIC = -2 \cdot LL + p \cdot \log(n)$$

where p = number of parameters = K × (d + d(d+1)/2 + 1)

Choose K that minimizes AIC or BIC on a validation set.

## Worked Example

### Setup

**Data:** 60 points from 2 true clusters
- Cluster 1: N([0, 0], I), 40 points
- Cluster 2: N([5, 5], I), 20 points

**Task:** Use EM to recover the clusters (K=2)

### Initialization

```python
# Random initialization
μ₁ ← random point from X
μ₂ ← random point from X

Σ₁ = Σ₂ = I (identity matrix)

π₁ = π₂ = 0.5  (uniform)
```

Try: μ₁ = [0.5, -0.3], μ₂ = [6, 4.5]

### Iteration 1: E-Step

For each point, compute responsibility.

**Example: x = [0.2, 0.1] (near true cluster 1)**

```
N(x | μ₁, Σ₁) = N([0.2, 0.1] | [0.5, -0.3], I)
               ≈ 0.08  (fairly likely)

N(x | μ₂, Σ₂) = N([0.2, 0.1] | [6, 4.5], I)
               ≈ 0.0000001  (extremely unlikely)

r₁ = (0.5 × 0.08) / (0.5 × 0.08 + 0.5 × 0.0000001)
   ≈ 0.99999  (almost certainly cluster 1)

r₂ ≈ 0.00001
```

For all 60 points: Compute all $r_{ik}$ → 60 × 2 matrix

Result:
```
N₁ = Σ_i r_i1 ≈ 50.3  (about 50 points softly assigned to cluster 1)
N₂ = Σ_i r_i2 ≈ 9.7   (about 10 points softly assigned to cluster 2)
```

### Iteration 1: M-Step

Update parameters using responsibilities.

```
μ₁^new = (1/50.3) × Σ_i (r_i1 × x_i)
       ≈ [0.1, -0.05]  (moved toward true cluster 1 center)

μ₂^new = (1/9.7) × Σ_i (r_i2 × x_i)
       ≈ [5.2, 4.8]   (moved toward true cluster 2 center)

Σ₁^new = (1/50.3) × Σ_i (r_i1 × (x_i - μ₁^new)(x_i - μ₁^new)^T)
       ≈ [[1.1, 0.05], [0.05, 1.0]]  (close to identity)

Σ₂^new ≈ [[1.0, -0.1], [-0.1, 1.1]]

π₁^new = 50.3/60 ≈ 0.84  (84% cluster 1)
π₂^new = 9.7/60 ≈ 0.16   (16% cluster 2)
```

**LL after iteration 1:** -120.5

### Iteration 2-5: Refinement

E-step and M-step repeat. Parameters converge:

```
Iteration 2: LL = -110.2  (improvement of 10.3)
Iteration 3: LL = -105.5  (improvement of 4.7)
Iteration 4: LL = -104.1  (improvement of 1.4)
Iteration 5: LL = -103.8  (improvement of 0.3) ← converging
```

### Final Result (Iteration ~10)

```
μ₁ ≈ [0.05, 0.02]     (recovered cluster 1!)
μ₂ ≈ [5.1, 5.0]       (recovered cluster 2!)

Σ₁ ≈ I  (roughly identity, correct)
Σ₂ ≈ I  (roughly identity, correct)

π₁ ≈ 0.67  (60/90 = 0.667, correct)
π₂ ≈ 0.33  (30/90 = 0.333, correct)

LL ≈ -103.2  (plateaued)
```

### Prediction on New Data

For a new point x_test = [0.3, -0.2]:

```
r_1 = (0.67 × N(x_test | μ₁, Σ₁)) / [...]  ≈ 0.98

Predicted cluster: 1  (with 98% confidence)
```

## Key Takeaways

1. **EM is an iterative algorithm** that alternates E-step (responsibilities) and M-step (parameter updates)

2. **E-step: Soft assignments** — Each point gets a probability for each cluster

3. **M-step: Weighted updates** — Parameters updated using weighted contributions from all points

4. **Convergence: Monotonic** — LL always improves (or stays same)

5. **Trade-offs:**
   - Soft clustering is more realistic than hard clustering
   - Better handles boundary points
   - More computationally expensive than K-means

6. **Practical considerations:**
   - Initialize carefully (k-means++ or multiple random starts)
   - Monitor convergence (log-likelihood or parameter change)
   - Handle edge cases (empty clusters, singular matrices)
   - Use AIC/BIC to select K

7. **When to use:**
   - Need probabilistic assignments (confidence levels)
   - Want to model cluster uncertainty
   - Have sufficient data and computational resources
